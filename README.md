# otp-service

REST API выдачи и проверки одноразовых кодов с защитой от перебора и спама (ТЗ 6, INAI 2026).

Продукт: вход по SMS для малого бизнеса в Кыргызстане (доставка, магазин, запись к врачу), который не даёт перебрать код и не даёт ботам сжечь бюджет на SMS.

## Запуск

Python 3.12+, без Docker и внешних сервисов. Одной строкой из корня репозитория (Linux / macOS):

```
cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt && uvicorn app.main:app --workers 1 --no-proxy-headers
```

Windows (PowerShell): то же, но `python -m venv .venv; .venv\Scripts\Activate.ps1`.

Сервис — http://127.0.0.1:8000, Swagger — http://127.0.0.1:8000/docs.

- venv нужен: на свежих Debian / Ubuntu `pip install` в системный Python запрещён (PEP 668). Нет модуля venv → `sudo apt install python3-venv`.
- Ровно 1 worker: состояние и lock, который делает `verify` атомарным, живут в одном процессе.
- `--no-proxy-headers`: IP клиента — адрес соединения. Без флага uvicorn верит `X-Forwarded-For` с `127.0.0.1`, и перебор с подменой заголовка обошёл бы лимит 20 `verify` в минуту с одного IP.
- Время реальное, режима подмены часов в сервисе нет: `advance` в сценариях — обычное ожидание. Тайминги можно ускорить через env (см. «Настройки»).

## Доставка кода («SMS»)

Каждая выдача дописывается строкой JSON в `outbox/sms.jsonl` **в корне репозитория** (не в `backend/`):

```
{"ts": "2026-11-21T09:00:00+06:00", "msisdn": "996770730000", "code": "012345"}
```

Актуальный код номера — последняя строка для него. Другой путь — env `OTP_OUTBOX`. Сервис этот файл не читает, HTTP-метода получения кода нет. Открытый код есть только здесь: в хранилище — HMAC, в журнале и логах — ни кода, ни хеша.

## API

| Метод | Путь | Тело | Ответы |
|---|---|---|---|
| POST | `/otp/send` | `{"msisdn": "996770730000"}` | 200, 400, 423, 429 (+ `Retry-After`), 503 |
| POST | `/otp/verify` | `{"msisdn": "996770730000", "code": "012345"}` | 200, 400, 401, 410, 423, 429 |
| GET | `/events` | — | последние 200 событий безопасности |
| GET | `/stats` | — | счётчики событий по типам с запуска и `saved_som` |
| GET | `/stats/history` | — | атаки за 24 ч по 15 минут (перебор, SMS pumping, сэкономлено сом), считаются из `security.log`, поэтому переживают рестарт |
| GET | `/dashboard` | — | дашборд безопасности: «сэкономлено N сом», отбитые атаки, лента событий (обновляется раз в 2 с) |
| GET | `/demo` | — | вход в выдуманный сервис доставки Barni & Go через `send` / `verify`; код — из `outbox/sms.jsonl`. Панель «Для жюри» — лог запросов и 20 параллельных `verify` одним кодом |

Тело ответа — `{"detail": "<причина>"}`. Некорректный JSON или формат — 400 (не 422).

- `msisdn` — строка ровно из 12 цифр, начинается с `996`; `code` — строка ровно из 6 цифр (`000000` допустим).
- Код — `secrets.randbelow(10**6)`, живёт 120 с (на 120-й секунде уже 410), одноразовый; новый `send` аннулирует предыдущий код.
- `send`: не больше 3 выдач за 10 минут, между 1-й и 2-й — 30 с, между 2-й и 3-й — 60 с, после 3-й — 120 с.
- `verify`: 5-й неверный код → 423, номер заблокирован на 15 минут (и `verify`, и `send` → 423).
- Лимит по IP: 20 `verify` в минуту по всем номерам, 21-й → 429. Учитывается любой `verify`, включая 400.
- Параллельные `verify` одним верным кодом: 200 ровно у одного, остальные 401.
- Журнал безопасности (выдача, неверный ввод, повтор использованного кода, блокировка, лимиты) — JSON lines в `security.log` в корне репозитория (env `SECURITY_LOG`) и в `GET /events`.

## Настройки (env)

Все необязательны, дефолты = ТЗ. Можно задать в `.env` в корне репозитория или в `backend/`.

| Переменная | Дефолт | Что |
|---|---|---|
| `OTP_TTL` | 120 | срок жизни кода, с |
| `SEND_WINDOW`, `SEND_MAX` | 600, 3 | окно и число выдач на номер |
| `SEND_DELAY_1/2/3` | 30, 60, 120 | задержка после 1-й, 2-й, 3-й выдачи, с |
| `VERIFY_MAX_FAILS`, `LOCK_SECONDS` | 5, 900 | неверных вводов до блокировки и её длительность, с |
| `IP_WINDOW`, `IP_MAX` | 60, 20 | окно и число `verify` с одного IP |
| `SEND_IP_MAX`, `SEND_IP_WINDOW` | 0, 600 | лимит выдач с одного IP против SMS pumping; `0` — выключен |
| `SMS_PRICE_SOM` | 1.04 | цена одной SMS для «сэкономлено» (минимальная официальная цена Beeline KG) |
| `OTP_SECRET` / `OTP_SECRET_FILE` | случайный при старте | HMAC-ключ: строка или файл (создаётся при первом старте) |
| `OTP_OUTBOX` | `<корень>/outbox/sms.jsonl` | канал доставки кода |
| `SECURITY_LOG` | `<корень>/security.log` | журнал безопасности |
| `REDIS_URL` | — | бонус: хранилище в Redis; без него — в памяти |

Некорректное значение (не число, отрицательное, дробный лимит, `SEND_MAX=0`) → сервис не стартует с понятной ошибкой.

## Проверка

Из `backend/`, с [uv](https://docs.astral.sh/uv/) (или в venv из «Запуска»: `pip install pytest`, дальше `python ...` вместо `uv run python ...`):

| Что | Команда |
|---|---|
| Тесты (сценарии жюри, лимиты, блокировки, параллельные запросы, атаки) | `uv run pytest` |
| Сценарии в формате жюри с пошаговым логом, подменённые часы | `uv run python scripts/scenarios.py` |
| То же на реальном uvicorn и реальном времени (~3 мин) | `uv run python scripts/scenarios.py --live` |
| Атака на запущенный сервер | `uv run python scripts/attack.py` |

`attack.py` — три атаки по 1000 запросов на свежие синтетические номера:

- `brute` — перебор кода одного номера с `127.0.0.1`;
- `spread` — распределённый перебор по 50 номерам с одного IP (`127.0.0.2`);
- `pump` — SMS pumping: 1000 `send` по 50 номерам.

Атаки подключаются с разных loopback-адресов, как стенд жюри; сервер берёт IP из соединения. Выбрать атаки: `attack.py brute pump`, другой сервер: `--url`. Exit code 1, если хоть один код угадан.

```
[brute] from 127.0.0.1
  verify responses: 401x4  423x16  429x980   (0.8 s)
  codes checked by the server: <= 5 of 1000, guessed: 0
  ATTACK STOPPED: number locked after 5 wrong codes (423), IP limited to 20 verify/min across all numbers (429)

[spread] from 127.0.0.2
  verify responses: 401x20  429x980   (0.8 s)
  codes checked by the server: <= 20 of 1000, guessed: 0
  ATTACK STOPPED: IP limited to 20 verify/min across all numbers (429)

[pump] from 127.0.0.1
  send   responses: 200x50  429x950   (0.8 s)
  SMS sent: 50 of 1000, rejected: 950, saved at least 988.00 som
  ATTACK STOPPED: send delays and the 3-per-10-min window reject repeats (429)
ALL ATTACKS STOPPED
```

Перебор одного номера останавливает блокировка после 5 ошибок, распределённый — лимит 20 `verify` в минуту с IP: из 1000 догадок с кодом сравнивается не больше 5 и 20.

## Наши трактовки

Уточнения v1.1 этого не задают, поэтому решили так:

- Порядок проверок в `verify`: 429 (лимит по IP) → 400 (формат) → 423 (номер заблокирован) → 401 (нет активного кода или он использован) → 410 (истёк) → 401 (неверный код; на 5-й — 423).
- Порядок проверок в `send`: 400 (формат) → 423 (номер заблокирован) → 429 (задержка или 3 выдачи в окне).
- Отказы 429 в окно IP-лимита не попадают: атакующий получает ровно 20 `verify` в минуту.
- Истёкший код остаётся до нового `send`: повторный `verify` снова → 410.
- Блокировка аннулирует активный код.
- Счётчик ошибок привязан к номеру, а не к коду: иначе `send` между попытками обнулял бы защиту. Сбрасывается при успешном `verify` и по окончании блокировки.
- `Retry-After` (целые секунды, вверх) — у 429 и 423 в `send`: до ближайшего разрешённого `send` или до конца блокировки.
- `ts` в outbox — в `+06:00` (Бишкек).
- `msisdn` или `code` не строкой (например, числом в JSON), глубоко вложенный JSON → 400.
- Сбой записи в outbox → `send` 503: код не сохраняется, действующий код не трогается. Redis недоступен → 503.
- Лимит `send` по IP (`SEND_IP_MAX`) по умолчанию выключен: со включённым сценарии с `send` на разные номера с одного IP получили бы лишний 429.
- Отклонённые `send` (423, 429) пишутся в события с `saved_som` = `SMS_PRICE_SOM`: дашборд показывает «сэкономлено не меньше N сом».
- Номер без активности 24 ч (`max(SEND_WINDOW, OTP_TTL, LOCK_SECONDS, 86400)`) забывается целиком (счётчик ошибок и истёкший код) — одинаково в памяти и в Redis. До этого истёкший код отвечает 410.

## Docker Compose + Redis (бонус)

```
docker compose up --build
```

Backend на http://localhost:8000, состояние — в Redis с TTL, коды — в `outbox/sms.jsonl` в корне репозитория. HMAC-ключ создаётся один раз в отдельном volume (не в Redis и не в git): после перезапуска backend выданные коды остаются действительными. `REDIS_URL` без `OTP_SECRET` или `OTP_SECRET_FILE` не запустится: после рестарта новый ключ сделал бы верные коды неверными.

IP-лимит в compose общий для всех локальных клиентов: docker-proxy подменяет адрес источника, и `127.0.0.1` и `127.0.0.2` приходят в backend как один IP шлюза Docker. Сценарии с разными IP проверяйте запуском без Docker (команда выше).

- [x] Журнал событий безопасности без кодов
- [x] `scripts/attack.py`: перебор одного номера и по 50 номерам с одного IP — оба остановлены

Бонусы и продукт:

## Не успели / вне рамок

- Реальная отправка SMS: вместо SMSC оператора (SMPP) — файл `outbox/sms.jsonl`; остальная логика та же.
- Режим подмены часов для проверки: время в сервисе реальное, ускорить сценарии можно через env (см. «Настройки»).
- Лимит по IP в Docker Compose различает клиентов только при запуске без docker-proxy (см. «Docker Compose»).
